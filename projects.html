  1. Injection frameworkC++17 · NT native API · driver

    NtInjector (NtLoader)

    A Windows injection framework that avoids the Win32 wrapper layer entirely, no static IAT entries, every function pointer resolved at runtime by walking the PEB and parsing exports. Configuration is JSON-driven (ntcfg.json) and the same binary drives both user-mode and driver-backed injection paths.

    Manual map
    In-memory PE mapping with relocations, imports, TLS callbacks, and SEH, without registering the module in the PEB loader lists. Optional header and section wipe (.pdata, .rsrc, .reloc).
    LdrLoadDll stub
    Writes a small stub plus LDR_DATA into the target and runs it via NtCreateThreadEx.
    User-mode APC
    Enumerates threads with NtQuerySystemInformation and queues LdrLoadDll with NtQueueApcThread so it fires the next time the target hits an alertable wait.
    Kernel driver
    Dispatches injection through a custom driver (\??\NtKrnldrv) and unloads once it's done.

  2. Graphics hookingC++ · MinHook · GDI

    Screenshot detection bypass

    A hook on gdi32!BitBlt that returns a clean copy of the framebuffer to screenshot-based scanners while overlays keep rendering in test builds. Small research toy, not a product, the interesting part is how many anti-cheat capture paths still rely on GDI.

    BitBlt hook
    Filters overlay layers out of screen-capture buffers.
    Test target
    Ships with a dummy overlay process to reproduce the capture path.

  3. Binary analysisPython · C++ · ZydisPrivate tooling

    PE Analyzer Suite

    Tooling I use to look at incoming samples. Python scripts do the boring part, parsing PE/ELF headers, dumping embedded binaries by computing exact offset and size, running heuristic scans over strings and section entropy. A separate C++ tool uses Zydis to trace dynamic import resolution when I need to look at how a sample resolves GetProcAddress.

    Embedded binary extraction
    Finds nested executables inside a host binary and dumps them by the exact raw offset and size, no scanning heuristics after the header is located.
    Heuristics
    Section entropy anomalies, string scans for C2 patterns, Discord webhooks, port-forwarding tunnels, common loader markers.
    Disassembly
    Zydis-backed x86/x64 pass for tracing dynamic import resolution and following calls to GetProcAddress.
